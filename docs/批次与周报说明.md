基于你提供的 `StockerAI-A-v6(1).zip` 修改，保留邻里小店风格。新增页面使用英文，与原有界面一致。本说明为中文。

## 1. 临期批次管理

左侧点击 **Expiry & batches**。

- 每个批次记录：商品、批次编号、数量、到货日期、标签上的实际到期日期和备注。
- **Label existing stock**：给已经计入库存的商品补录批次日期，库存总量不增加。最多可登记尚未分配到批次的数量。
- **New delivery**：登记真正的新到货，同时增加库存和该批次数量；不要把已经在库存页登记过的到货再登记一次。
- 可设置提前 1–30 天提醒；到期当日、已经过期和即将到期分别显示。支持搜索、完整表格和 CSV 下载。
- **Sold**：扣减指定批次和总库存，同时记入当天销售。已过期批次不能登记为销售。
- **Waste / discarded**：报损，只扣库存，不增加销售额。
- **Returned to supplier**：退回供应商，只扣库存，单独记为退货，不算作报损。
- 批次编号、日期和备注可以更正，操作留下记录。耗尽批次可在 History 中查询。

### 与原有库存功能如何配合

在原有库存页面登记销售时，系统优先扣减尚未过期且到期日最早的批次，再使用没有日期的库存。不会自动销售过期批次。

直接修改商品库存总量或登记盘点时，减少的数量先由没有日期的库存承担；仍不够时，按先到期顺序调整批次数量，并留下盘点调整记录。增加的盘点数量保持“未登记批次日期”，需要另行补录。

**导入历史销售文件不会再次扣减当前批次库存。** 已经导入的销售也不要再手工登记一次。系统无法仅凭历史销售推算货架上每个批次的实际余量，应以盘点为准。

批次信息以实际录入日期为依据；没有日期的库存仍采用 v6 的保质期估算提醒。未登记日期的库存不等于没有临期风险。过期批次在确认报损或退货前仍保留在物理库存总量中，采购前先处理这些库存。

新建的演示店铺含 4 个 `DEMO-` 批次，日期是演示示例，不是真实商品资料。升级旧工作区不会替真实库存编造到期日。

## 2. 一周经营小结

左侧点击 **Weekly review**。无需 AI 密钥即可使用。

- 默认选择最新已完成销售日，统计截至该日的连续 7 个日历日，对比此前 7 天；可以自行选择结束日期。
- 显示已记录销售额、销量、日期覆盖情况、收入变化、每日销售图和按收入排序的畅销商品。
- 缺少记录的日期显示为空缺，不假装是零销量。两期均覆盖 7 天且前期收入大于零时才展示变化百分比。全店在日历中标记为 Closed 的日期可作为已知停业日。
- 展示当前缺货、积压、临期批次，并结合补货建议和近期节假日／促销，列出接下来 7 天值得做的事情。
- 报损按所选期间内记录的批次报损汇总，采用批次当时保存的成本。没有成本的记录会说明；退回供应商不计入报损。
- 支持下载 **Markdown 完整周报**和 **Excel 数据表**，附统计日期与数据说明。

销售部分是所选历史期间的实际记录；库存提醒和下一步建议是当前状态。系统不会将当前缺货误当作过去一周的缺货，也不会编造历史损失或节省金额。

## 3. 启动与升级

解压完整文件夹后，使用原有 Mac `.command` 或 Windows `.bat` 启动文件。仍需 Python 3.10+；依赖安装方式沿用 v6。默认打开本机地址，使用时保留启动窗口。

本次开发预览：`http://127.0.0.1:8502/?ws=v7demo20261102`，其中是独立演示数据。

如果需要沿用旧版记录：先关闭旧程序并备份旧文件夹，再将旧版 `data` 文件夹复制到新版文件夹中，打开原先带 `ws=` 的工作区地址。新版会增加批次相关表，保留原商品、销售、模型、采购审核记录和设置。原有工作区保留／清理机制沿用 v6；本次没有修改其策略。

压缩包不包含本机演示数据库、虚拟环境或真实密钥；原 v6 ZIP 和此前的版本未覆盖。
